## What went well

- **Reusable frameworks held up.** The Story 0.4 catalog editor was reused verbatim for ticket categories (1.1); the Story 1.3 `policy_scope` subtree gate was reused by 1.4/1.5/1.6/1.7/1.8; and 1.8's dashboard-widget convention (`<mod>/_dashboard_widget`) + toolbar `export_url` are now generic for Epics 2–7. No framework rewrites.
- **Incremental slicing was sound.** 1.7 (closure) cleanly *composed* 1.4 (status) + 1.6 (voter gate) + 0.15 (Voter sentiment) with no rework — evidence the story boundaries were drawn well.
- **Isolation discipline held.** Every org-scoped domain model (Ticket, TicketStatusChange, TicketFollowUp) shipped with its release-gate tenant-isolation test.
- **Upfront schema paid off.** `voter_id`/`closed_at` (1.2) and `sentiment_*` (0.15) existed before the stories that used them, so 1.6/1.7 needed no migrations.

## What was harder / surprises

1. **Namespaced-model form params (1.2).** `form_with model: @ticket` on `KitchenCabinet::Ticket` scoped params to `kitchen_cabinet_ticket[...]`, but the controller read `require(:ticket)` — the real form would have silently failed. Caught by an `assert_select` on the rendered hidden field, **not** by the POST test (which posts params directly).
2. **Unpinned gem drift (pagy, 1.3).** `gem "pagy"` (no version) resolved to a rewritten major (**43.7.0**, no `Pagy::Backend`/`Frontend`). Cost a detour: shipped an interim manual paginator, then adopted the real `Pagy::Method` API and **pinned** it.
3. **Charting not wired (1.8).** chartkick renders a container but no JS adapter (Chart.js) is pinned/imported, so charts don't draw and "Export Chart"/Bar-Pie-Line toggle were left as placeholders. Excel export (the concrete FR49 deliverable) is fully working + Roo-tested.
4. **No sprint tracking.** Progress is tracked per story file only (no `sprint-status.yaml`), the same gap that caused the Epic 0 story-file backfill earlier.

## Lessons / conventions to carry into Epic 2

- Namespaced models (Epic 2's `CadreActivity` + detail models) need: `self.table_name` pinned, explicit `belongs_to … class_name:`, and `form_with … scope:` — and a test that asserts on the **rendered form**, not just a direct POST.
- Pin every gem in the stack list with a version constraint.
- Reuse the 1.8 widget + `export_url` conventions directly for the "Recent cadre activity" widget (already registered in `dashboard_widgets_for`) and cadre export.
- Reuse the Tier-2 append-log shape (1.4/1.5) and the `policy_scope` subtree gate for all cadre reads/writes.
